# Optional PAN — requirements

- R1: Default off even if credential paths exist; normal chat works without PAN.
- R2: Runtime enable/disable; disabling stops subscriptions and subsequent delivery from stopped adapters.
- R3: Document the current DSHmux client configuration and protocol only; PAN counterpart implementation/deployment is out of scope.

The user's implementation request authorizes this scoped change.

- R4: Public PAN documentation uses example.com placeholders and does not disclose our service URLs.
